# 固件修复摘要（2026-08-21 ~ 2026-08-24）

设备：润芯微 Gemini-S1（全志 R528 + SPI NAND，openvela/nuttx）

## 1. 白屏修复（08-21，已验证）

- **根因 1**：`r528_boot.c` 中 `#if defined(CONFIG_LCD_FRAMEBUFFER)` 分支遮蔽了 `CONFIG_LCD` 分支 → `/dev/lcd0` 从未注册 → luncher_mini 白屏。
- **根因 2**：`CONFIG_LV_DRAW_BUF_ALIGN` 为 64 时裸 `lv_malloc` 缓冲不满足对齐断言（恢复上游值 1）。
- **修复**：删 `CONFIG_LCD_FRAMEBUFFER=y`；`CONFIG_LV_DRAW_BUF_ALIGN=1`（后者与上游一致，不产生 diff）。
- **验证**：屏幕显示 luncher_mini 主题界面，与出厂固件一致。

## 2. BLE 根因 1：KVDB_SERVER 缺失（08-22，已验证）

- **现象**：bluetoothd 启动卡死在 `bt_log_server_init` 的 `property_get_int32`（等 KVDB 属性服务）。
- **根因**：KVDB 服务端（kvdbd）未随系统启动。
- **修复**：确保 `CONFIG_KVDB_SERVER=y` 在 defconfig 与运行 `.config` 中一致生效。
- **验证**：kvdbd 在跑、ZBLUE 5.4 栈初始化成功、socket 服务注册、ai_agent 拿到 BT 实例。

## 3. BLE 根因 2：H5 slip 层栈溢出（08-23，已验证）

- **现象**：controller 重发风暴（同一 0xfc20 事件 40+ 次）、`err: seq:4 != rxack:3` seq 失步、H5 链路死锁、fw 任务卡死。
- **根因**：`CONFIG_BLUETOOTH_HCI_RECV_STACKSIZE=4096`（bt_recv/bt_fw 任务栈）< `CONFIG_BLUETOOTH_SLIP_TXBUFSIZE=4160`（`bt_slip_send_packet` 局部数组）→ ACK 发送路径 4 层嵌套栈溢出 → ACK 损坏。
- **修复**：`CONFIG_BLUETOOTH_HCI_RECV_STACKSIZE` 4096→16384、`CONFIG_BT_HCI_TX_STACK_SIZE` 4096→16384（见 firmware-fixes-board-defconfig patch）。
- **验证**：fw download 完成退出；HCI 命令序列 status 全 00；bth4_rx/h4_read 1:1 配对；零 err/FATAL。

## 4. BLE 根因 3：controller 扩展广播空中不发射（08-24，已验证）

- **现象**：ai_agent 全绿（advertising confirmed active）、HCI 三条 ext adv 命令（0x2036/0x2037/0x2039）status 全 00、无终止事件，但两台 iPhone 两个扫描 App 贴近板子均收不到任何包。
- **根因**：Realtek controller 接受扩展广播命令（status 00）但 ext adv PDU 空中不发射。
- **修复**：`ble_gatt.c` advertising 类型 `BT_LE_ADV_IND` → `BT_LE_LEGACY_ADV_IND`（传统 ADV_IND，见 ai-agent-ble-gatt-fixes patch）。
- **验证**：手机扫描到 `VelaClaw`，GATT server / NUS 注册日志完整。
